# Design: 待办事项显示功能

## Context
EPD-nRF5项目是一个运行在Nordic nRF5系列微控制器上的电子纸显示器固件。当前支持日历模式显示，用户希望在日历模式下显示待办事项，并通过蓝牙推送待办事项列表。由于电子纸的特性，全屏刷新需要2-15秒，因此需要使用局部刷新功能以提高更新速度。

## Goals / Non-Goals

### Goals
- 支持两种日历显示模式：完整日历模式和简洁日历+待办模式
- 在日历模式下显示待办事项列表
- 支持通过BLE接收待办事项数据（字符串格式）
- 支持通过BLE接收地址位置和天气信息（字符串格式）
- 使用局部刷新功能更新待办事项、地址位置和天气信息显示区域
- 待办事项、地址位置和天气数据持久化存储（Flash存储）
- 主要适配400x300屏幕尺寸（4.2英寸），更大尺寸按比例调整
- 简洁日历+待办模式采用新的GUI布局设计（参考React组件）

### Non-Goals
- 待办事项的编辑和删除功能（仅支持显示和更新）
- 待办事项的优先级和分类功能（第一版本）
- 待办事项的提醒功能
- 与外部待办事项服务（如Todoist）的集成

## Decisions

### Decision: 待办事项数据结构
使用简单字符串格式存储待办事项，不需要和日期关联，以推送内容为准，直接全量显示：
```c
typedef struct {
    char todo_string[64];  // 待办事项字符串（格式：`事项1; 事项2; ...`，最多60个字符+结束符）
} todo_data_t;
```

待办事项字符串格式：`事项1; 事项2; ...`
- 多个待办事项用分号`;`分隔
- 显示时按分号分割显示，每个事项一行
- 不需要显示日期和时间
- 字符串长度不超过60个字符（避免占用内存）

**Alternatives considered:**
- 使用结构化数据（日期、时间、文本分离）：被拒绝，因为用户要求简化处理逻辑
- 使用动态内存分配：被拒绝，因为nRF51系列RAM有限，且需要避免内存碎片
- 与日期关联：被拒绝，因为用户要求日程不需要和日期关联

### Decision: BLE命令格式

#### EPD_CMD_SET_TODO (0x40)
用于设置待办事项列表。

命令格式：
```
[0x40] [string_len] [todo_string...]
```

- `string_len`为待办事项字符串长度（1字节，0-60）
- `todo_string`为待办事项字符串（UTF-8编码，格式：`事项1; 事项2; ...`）

待办事项字符串格式：`事项1; 事项2; ...`（UTF-8编码）
- 多个待办事项用分号`;`分隔
- 字符串长度不超过60个字符
- 墨水屏收到推送后直接全量显示，不需要二次处理

#### EPD_CMD_SET_LOCATION (0x41)
用于设置左下角地址位置信息。

命令格式：
```
[0x41] [string_len] [location_string...]
```

- `string_len`为地址位置字符串长度（1字节，0-60）
- `location_string`为地址位置字符串（UTF-8编码，纯文本，直接原样显示）

地址位置字符串格式：纯文本，例如`上海 · 浦东新区 · 康桥`
- 字符串长度不超过60个字符
- 直接原样显示，不需要解析或格式化

#### EPD_CMD_SET_WEATHER (0x42)
用于设置天气信息。

命令格式：
```
[0x42] [string_len] [weather_string...]
```

- `string_len`为天气信息字符串长度（1字节，0-60）
- `weather_string`为天气信息字符串（UTF-8编码，格式：`温度,天气,湿度,风向,风力描述`）

天气信息字符串格式：`温度,天气,湿度,风向,风力描述`（UTF-8编码）
- 示例：`7.6,晴,56,东南,东南风 二级`
- 字段用逗号`,`分隔
- 字段顺序：温度（浮点数，如7.6）、天气（如"晴"）、湿度（整数，如56）、风向（如"东南"）、风力描述（如"东南风 二级"）
- 字符串长度不超过60个字符
- 显示时解析各字段并在GUI中格式化显示

**命令处理规则：**
- 所有命令仅在`MODE_CALENDAR_TODO`模式下生效
- 收到命令后，保存数据到Flash配置
- 如果当前显示模式为`MODE_CALENDAR_TODO`，触发相应区域的局部刷新
- 如果当前显示模式不是`MODE_CALENDAR_TODO`，仅保存数据，不触发刷新

**Alternatives considered:**
- 使用JSON格式：被拒绝，因为解析复杂且占用更多内存
- 使用分包传输：考虑支持，但第一版本假设数据可以一次性传输（MTU限制）
- 包含日期信息：被拒绝，因为用户要求日程不需要和日期关联
- 使用结构化命令（每个字段单独命令）：被拒绝，因为会增加命令数量，使用逗号分隔的字符串格式更简洁

### Decision: 显示位置和布局

支持两种日历显示模式：

#### 模式1：完整日历模式
- 保持当前已有的完整日历设计
- 待办事项显示在日历下方（可选，第一版本可能不在此模式显示待办）

#### 模式2：简洁日历+待办模式（主要适配400x300，参考React组件设计）

**整体布局（从上到下）：**

1. **顶部状态栏**（高度约20-24像素）
   - 左侧：电池图标 + 电池电压（如`3.85V`）
   - 右侧：设备ID（如`ESP-A7F2`）
   - 使用小字体（9-11px），黑色边框分隔

2. **今日信息区域**（高度约50-60像素，带底部边框）
   - **左侧**：
     - 第一行：年月（红色，如`2026年1月`）+ 农历年份（如`乙巳年[蛇]`）
     - 第二行：日期（大号字体，如`13`）+ 星期（如`星期二`）+ 农历日期（红色，如`腊月十五`）
   - **右侧**：天气信息
     - 左侧：天气（大号字体，如`晴`）
     - 中间：温度（大号字体，如`15.5°`）
     - 右侧：湿度、风向（小号字体，竖排，如`湿度 45%`、`东南风 2级`）

3. **中间区域**（flex布局，占据剩余空间）
   - **左侧65%**：简洁日历
     - 周几标题行（7列，周末红色背景）
     - 日历网格（7列，多行）
     - 当日高亮显示（红色圆形背景，白色文字）
     - 周末日期红色显示
   - **右侧35%**：待办事项列表
     - 标题：`待办事项`（红色，小号字体）
     - 待办列表：
       - 每个待办事项一行
       - 左侧复选框（未完成：空框，已完成：实心框）
       - 右侧文本（已完成：删除线+半透明）
       - 使用小号字体（11px）

4. **底部**（高度约20-24像素，带顶部边框）
   - 左侧：地址位置信息（如`上海 · 浦东新区 · 康桥`）
   - 右侧：空气质量（如`空气质量 良`）

**尺寸适配：**
- 最小分辨率：400x300
- 更大尺寸：按比例调整日历文字间距和字体大小
- 使用`large_layout(data)`宏判断是否使用大尺寸布局（高度>=400）

**颜色方案：**
- 墨水屏支持：黑白红三色
- 背景：白色
- 文字：黑色（默认）、红色（强调，如日期、标题、周末）
- 边框：黑色

**Alternatives considered:**
- 在日历日期上叠加标记：被拒绝，因为会遮挡日期显示
- 使用独立页面：被拒绝，因为用户希望在日历模式下同时看到
- 上下布局：被拒绝，因为左右布局更适合400x300屏幕的横向空间利用

### Decision: 局部刷新实现
使用EPD驱动的局部刷新功能（`_setPartialRamArea`和`UC81xx_PTIN`/`UC81xx_PTOUT`或SSD16xx的局部刷新命令）。

**刷新区域定义：**

1. **待办事项区域刷新**（`EPD_CMD_SET_TODO`）
   - 区域：右侧65%的待办事项列表区域
   - 坐标：`x = width/2 + 5, y = today_info_height + 5, w = width/2 - 10, h = todo_area_height`

2. **天气信息区域刷新**（`EPD_CMD_SET_WEATHER`）
   - 区域：今日信息区域的右侧天气部分
   - 坐标：`x = weather_x, y = today_info_y, w = weather_width, h = today_info_height`

3. **地址位置区域刷新**（`EPD_CMD_SET_LOCATION`）
   - 区域：底部地址位置信息区域
   - 坐标：`x = 5, y = height - footer_height, w = footer_width, h = footer_height`

**刷新触发条件：**
- 仅在`MODE_CALENDAR_TODO`模式下触发局部刷新
- 如果当前显示模式不是`MODE_CALENDAR_TODO`，仅保存数据，不触发刷新
- 刷新前需要重新绘制相应区域的GUI内容到显示缓冲区

**Alternatives considered:**
- 全屏刷新：被拒绝，因为刷新时间过长（2-15秒）
- 逐行刷新：被拒绝，因为实现复杂且可能造成显示异常
- 同时刷新多个区域：被拒绝，因为需要分别计算每个区域的坐标，分别刷新更精确

### Decision: 数据存储
待办事项、地址位置和天气信息数据存储在Flash中（使用FDS/FStorage），与EPD配置一起存储。

配置结构体扩展：
```c
typedef struct {
    // ... existing fields ...
    char todo_string[64];      // 待办事项字符串（格式：`事项1; 事项2; ...`，最多60个字符+结束符）
    char location_string[64];   // 地址位置字符串（纯文本，最多60个字符+结束符）
    char weather_string[64];    // 天气信息字符串（格式：`温度,天气,湿度,风向,风力描述`，最多60个字符+结束符）
} epd_config_t;
```

**Alternatives considered:**
- 仅存储在RAM中：被拒绝，因为设备重启后数据会丢失
- 使用独立存储区域：被拒绝，因为需要复用现有的存储机制
- 使用更大的字符串缓冲区：被拒绝，因为Flash空间有限，60字符已足够大多数使用场景

### Decision: 日历显示模式配置
日历显示模式通过`EPD_CMD_SET_TIME` (0x20)命令的`mode`参数配置，复用现有的时间同步命令。将日历和日历+日程作为两种独立的显示模式，而不是日历模式的子类型：

- `mode=1`: 完整日历模式（`MODE_CALENDAR`）
- `mode=2`: 时钟模式（`MODE_CLOCK`）
- `mode=3`: 日历&日程模式（`MODE_CALENDAR_TODO`）

命令格式：
```
[0x20] [timestamp(4字节)] [timezone(1字节)] [mode(1字节)]
```

在`display_mode_t`枚举中新增`MODE_CALENDAR_TODO = 3`，作为独立的显示模式。当收到`mode=3`时，固件直接设置`display_mode`为`MODE_CALENDAR_TODO`并保存到Flash。

GUI层根据`display_mode`直接判断使用哪个绘制函数：
- `MODE_CALENDAR`: 调用`DrawCalendar()`绘制完整日历
- `MODE_CALENDAR_TODO`: 调用`DrawCalendarTodo()`绘制简洁日历+待办

HTML网页界面提供下拉菜单和"应用"按钮，允许用户选择并应用日历显示模式。选择"完整日历"时调用`syncTime(1)`，选择"日历&日程"时调用`syncTime(3)`。

**Alternatives considered:**
- 使用`calendar_mode`作为子类型：被拒绝，因为将两种模式作为独立的显示模式更清晰，代码逻辑更简单
- 使用`EPD_CMD_SET_CONFIG`命令：被拒绝，因为需要发送完整78字节配置，而`SET_TIME`命令更简洁
- 使用独立的BLE命令切换模式：被拒绝，因为复用现有的时间同步命令更简单且统一
- 仅通过固件代码配置：被拒绝，因为用户需要通过Web界面灵活切换模式

## Risks / Trade-offs

### 风险1: 内存限制
- **风险**: nRF51系列RAM较小，存储待办事项字符串可能占用过多内存
- **缓解措施**: 
  - 限制待办事项字符串长度为60个字符（避免占用内存）
  - 使用固定大小的缓冲区（64字节，包含结束符）
  - 如果内存不足，可以进一步减少字符串长度限制

### 风险2: 局部刷新兼容性
- **风险**: 不是所有EPD驱动芯片都支持局部刷新
- **缓解措施**: 
  - 检查驱动是否支持局部刷新
  - 如果不支持，回退到全屏刷新（但会显示警告日志）

### 风险3: 文本编码和显示
- **风险**: 中文文本需要UTF-8编码，字体渲染可能有问题
- **缓解措施**: 
  - 使用现有的中文字体（`u8g2_font_wqy9_t_lunar`）
  - 限制文本长度以确保显示完整

### 风险4: BLE传输限制
- **风险**: MTU限制可能导致待办事项列表无法一次性传输
- **缓解措施**: 
  - 第一版本假设可以一次性传输
  - 如果遇到问题，后续版本可以实现分包传输

## Migration Plan
1. 新增BLE命令和数据结构定义（`EPD_CMD_SET_TODO`, `EPD_CMD_SET_LOCATION`, `EPD_CMD_SET_WEATHER`）
2. 实现待办事项、地址位置、天气信息数据接收和存储
3. 修改GUI绘制函数`DrawCalendarTodo`以使用新的布局设计
   - 实现状态栏绘制函数
   - 实现今日信息区域绘制函数（包含天气信息解析和显示）
   - 修改日历和待办事项布局
   - 实现底部地址位置信息绘制函数
   - 支持400x300最小分辨率，更大尺寸按比例调整
4. 实现局部刷新功能（待办事项、天气、地址区域）
5. 更新Web界面以支持配置日历显示模式
6. 更新Web界面以支持推送待办事项、地址位置和天气信息
7. 测试各种屏幕尺寸和驱动芯片
